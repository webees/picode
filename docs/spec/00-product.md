# 00 — 产品

## 定义

**picode** = 基于 [Pi](https://pi.dev/) 的 **通用多智能体编码运行时**（project OS）。

- 目标驱动，可长跑至 goal 完成/取消。  
- 覆盖：需求共创、规划、分块并行实现、测试证据、交接、门禁合并、**文档小组记忆与知识**、工程主责 brief。  
- **领域中立**：不绑定语言、行业或专项任务类型。  

## 非目标

- 不是单一 IDE 插件。  
- 不是通用 IM 产品。  
- 不在核心规范中预设业务 profile 清单。  

## 技术基线

|层|选型|
|----|------|
|Agent 运行时|Pi（短会话）|
|多 agent 消息|pi-messenger（或等价）+ **bus 适配层**|
|编排|自研编排器 + Pi 扩展|
|状态/档案|**仅文件**（`runs/<run_id>/`）|
|差异化能力|使用方 profile + Pi skills|

## 核心组织原则

1. **三三制**：每个激活的工作环节 = 领导 / 执行 / 监督（见 02-organization）。  
2. **封闭房间**：仅成员可 post（见 02、04）。  
3. **先确认再实现**：intake 完成前 MUST NOT spawn 实现三角。  
4. **先交接再解散**：实现三角 MUST 完成 handoff ack 后才 dissolved。  
5. **信息多层过滤**：工作组专一；资料申请 + 工程主责审阅 + **文档小组**下发（见 07、15）。  
6. **Git worktree + Bus + 工具画像** 为强制平台基线（见 06、07、09）。  
7. **尽量可配置**：房间/角色展示名、三角绑定、工具画像、超时、文案、路径等（见 13-configuration）；逻辑 id 稳定。  
8. **文档小组**为一级三人编制：掌管 run 记忆与知识管理，并向工程主责汇报（见 **15-docs-cell**）。  
9. **人事部**按任务招聘实现三人组：工程主责提标准 → 人设核对 → 建组（见 **16-hr-cell**）。
