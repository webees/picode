# run-lead 自治规划 — 会话生命周期：run 收尾自动休眠 + 跨 run 残留审计清理（run-2026-08-13T17-25-34-974Z · self_evolve · scale L · 合并 E 纪要）

> 目标（product_acceptance，宽松，run-lead 自主决策）：
> 1. run 收尾（goal completed/dissolved）时平台席自动休眠，不残留 awake
> 2. 提供会话残留检查/清理手段（CLI 可审计跨 run 残留 awake 会话）
> 3. max_awake 不再被已完成 run 的残留会话占满
>
> 背景（两次真实事故）：
> - **事故 1**：max_awake=15 被跨 run 残留 awake 会话占满（44 个：已完成 run 的平台席/三角从不自动 sleep，事件重新唤醒）→ 新任务无法 spawn
> - **事故 2**：监督者 setup 脚本 bug 致新 run 混入历史 chunk/会话（幽灵数据）→ 界面显示无关任务。根因已修（setup-tasks `RUN_CHUNKS` 白名单，3b1b0cd）
>
> 基线：main = fe88c74（事故 2 修复已并入）。本轮在基线之上做会话生命周期闭环。
> 数据面：`sessions/*.yaml`（SessionStore 状态机）+ `goal.yaml`（终态）+ `runs_root`（跨 run 枚举）。

### D72 run 收尾自动休眠平台席（修，本轮核心）

| # | 问题 / 候选 | 处置（决定） | 理由 |
|---|---|---|---|
| D72-1 | **根因确认** | `setGoalStatus` 仅写 goal 状态（run-store.ts:225），无任何会话副作用；`deriveEvents` 对终态 goal 只发 `TASK_DISSOLVED`（self-drive.ts:132-140）终止**三角**，**平台席（run-lead/pm/tpm/scout…17 席）从不 sleep** → 已完成 run 残留 awake | 事故 1 直接根因：收尾路径缺「平台席休眠」这一动作；TASK_DISSOLVED 只覆盖 task 三角 |
| D72-2 | **休眠对象判定** | **新增 `sleepPlatformSeats(dir, config)` 原语**：遍历 `SessionStore.list()` 中 `state==="awake"` 且 `taskIdOfAgent(agentId)===null` 的会话（平台席），逐个 `sleepAgent`（opencode/pi 后端一并关闭，D057）；幂等（非 awake 跳过，重复调用零副作用） | 平台席判定复用 `continuation.ts` 已导出的 `taskIdOfAgent`（status.ts:121 同款口径），零新语义；只动 awake，睡过/注册态天然安全 |
| D72-3 | **CLI 收尾路径** | `commands/goal.ts` 的 `goal set-status` 命令：当目标状态为 `completed`/`cancelled` 时，在 `setGoalStatus` 之后 **best-effort** 调 `closeRun(dir, config)`：① 对 `deriveEvents` 结果逐个 `applyEvent`（补发 TASK_DISSOLVED，终止尚未 dissolved 的三角）；② 再 `sleepPlatformSeats` | 人工 `goal set-status` 常发生在 guardian 未运行/已停机时（事故现场），CLI 必须自带完整收尾；失败不回滚状态变更（收尾 best-effort，残留可被 audit 清理） |
| D72-4 | **guardian 收尾路径** | `guardianTick`（self-drive.ts:476）：applyEvent 循环后读取 goal，若终态（completed/cancelled）→ `await sleepPlatformSeats`；结果入 `GuardianTickResult` 新增 `slept_platform: string[]` | 无人值守（guardian 运行中、CLI 未介入）也要收敛；与 CLI 路径共用同一原语，杜绝双份逻辑（对齐 E7 `shouldRunGate` 教训） |
| D72-5 | **run-store 保持纯净** | **不改** `setGoalStatus`（同步纯函数，单测面稳定）；收尾副作用只放命令层 + guardian 层 | 状态迁移与收尾副作用分离，可测、可审计 |
| D72-6 | **不引入规则表新事件** | 不加 `SESSION_EVENTS.RUN_CLOSED` / 不改 `SessMgrRule` / config rules | 规则表只有 wake 面（wake/sleep/terminate 按名单或 squad），平台席是固定集合，专用原语比配置面更简单；避免 config+rules-engine+自测四处联动 |

### D73 CLI 跨 run 残留审计 + 清理（修，本轮核心）

| # | 问题 / 候选 | 处置（决定） | 理由 |
|---|---|---|---|
| D73-1 | **现状缺口** | `session list/roster` 均单 run 视图（commands/session.ts），无法枚举跨 run 残留；事故后只能人肉翻 `runs/*/sessions/*.yaml` | 验收 #2 直接缺口：缺跨 run 只读审计面 |
| D73-2 | **新命令 `picode session audit`** | 新增子命令（`noRun: true`，跨 run 不需要 `--run`）：扫描 `runsRoot(repo, config)` 下全部 run 目录，逐 run 读 `goal.yaml.status` + `SessionStore.list()`，输出：`run_id / goal 状态 / awake 列表 / 终态标记`；汇总跨 run awake 总数（对照 `sess_mgr.max_awake`） | 验收 #2 主体：机械只读枚举，无副作用 |
| D73-3 | **残留定义** | 残留 = 该 run `goal.status ∈ {completed, cancelled}` 且仍存在 `state==="awake"` 的会话 | 与 D72 终态口径一致（goal 终态 = run 已收尾） |
| D73-4 | **`--clean` 清理** | `session audit --clean`：对每个残留 run 逐个调用 D72 的 `closeRun`（三角终止 + 平台席休眠），输出每 run 清理结果 | 验收 #2「清理手段」+ 事故 1 存量 44 个残留的回收路径；复用收尾原语，不另写一套 |
| D73-5 | **默认只读** | 不带 `--clean` 时零写（纯读 goal/sessions YAML）；`--run <id>` 可选限定单 run | 审计命令默认安全；清理显式 opt-in |
| D73-6 | **实现位置** | 新模块 `packages/orchestrator/src/session-audit.ts`（纯派生 `deriveAuditReport` + 执行器 `cleanResidual`）+ 挂到 `commands/session.ts` | 纯函数可单测；命令层保持薄 |
