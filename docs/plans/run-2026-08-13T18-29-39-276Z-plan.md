### D076 语义续跑（transcript.historySummary 注入续跑 prompt · 本轮核心）

| # | 问题 / 候选 | 处置（决定） | 理由 |
|---|---|---|---|
| D076-1 | **摘要来源**：哪条既有记录做「上一回合上下文」 | **`TranscriptStore.historySummary(agentId)`（P4 已有，直接复用）** | acceptance #2「摘要来自 transcript 既有记录，不新增数据源」——`transcript-store.ts:100-133` 已产出确定性启发式摘要（条数统计 + 最近 maxEntries 条可读要点，每条截断 120 字符；空转录/损坏返回 null）。`wakeWithOpencode`（opencode-adapter.ts:276）已用它注入 ready 消息（`## 历史要点摘要（转录恢复）`），机制成熟。**不采用** window-store.ts 的窗口压缩摘要（那是房间 bus 层 `RoomStore.compressWindow` 的折叠产物，与 per-agent 转录无关，属另一数据源） |
| D076-2 | **截断策略**：摘要注入的规模上限 | **复用 historySummary 现有截断，续跑场景取 `maxEntries: 8`** | historySummary 已按条截断（120 字符）且只取最近 N 条；续跑 prompt 保持轻量——固定模板 + ≤8 条要点（约 ≤1.2KB），不膨胀会话上下文；默认 `maxEntries`=20 是重 spawn 全量恢复用，续跑是「上一回合」增量场景，8 条足够覆盖最近完整回合 |
| D076-3 | **注入格式**：如何拼进续跑 prompt | **纯函数 `composeContinuationPrompt(summary: string \| null)`：null → 原样返回 `CONTINUATION_PROMPT`；非 null → 固定模板 + `\n\n## 上一回合要点（转录摘要）\n${summary}`**；feed 时经 `buildReadyMessage(env, composed)` 以独立 text part 追加 | 对齐 wakeWithOpencode 注入惯例（`## 历史要点摘要` 段标题风格）；**`CONTINUATION_PROMPT` 固定模板正文不变**——既有 continuation.test 断言 `msg.parts[].text.includes("继续推进")` 与转录落盘断言不受破坏。抽纯函数而非内联字符串拼接 → 可单测、无 I/O 副作用 |
| D076-4 | **空转录/损坏回退** | historySummary 返回 null → 走纯 `CONTINUATION_PROMPT`，行为与现版**逐字节一致** | 零回归语义：新 agent/无转录会话续跑时与 D066 完全等价；损坏文件由 historySummary 容错（返回 null），feed 不抛错 |
| D076-5 | **纯函数/幂等/预算不回归** | ① `deriveContinuationTargets` **零改动**（候选派生保持纯读）；② `feedContinuation` 保持「POST 成功才 `recordOutgoing`+`recordContinuation` +1」，摘要注入只影响消息文本内容，不动计数/幂等/重试路径；③ `composeContinuationPrompt` 新纯函数独立单测 | acceptance #3 直接保障面：idle 时钟（R3 D067）/平台席（D068）/gate（D068 C2）/遥测（D069）全部不动；既有 continuation.test 用例（含「投喂后紧接 sweep 不重复投喂」幂等用例）全绿即验收 |
| D076-6 | **新增数据/配置** | **零新增**：不新增数据源、不新增 config 字段、不新增状态文件 | 摘要读的是 continuation 每次 feed 已写入的 `transcripts/<agent>.jsonl`（feed 自身落盘 outgoing，天然成为下一轮摘要的输入——上一回合被投喂了什么，下一轮摘要就带什么），闭环无需新基建 |
| D076-7 | **文档落地** | DECISIONS 记 **D076**；decision-catalog §12.3（「续跑内容语义」）把「transcript 摘要注入（P4 historySummary）」从候选改为**已定**；operations.md 续跑语义小节补一句「续跑 prompt 含上一回合要点」 | 对齐前轮惯例（每轮 docs 层归档，E7/E8 均含）；§12.3 现文案正是「语义续跑，第二轮候选」，本轮落地改口径 |

**总纲**：语义续跑 = 在 `feedContinuation` 投喂时把既有 `historySummary`（maxEntries=8）拼进续跑 prompt，纯函数 `composeContinuationPrompt` 承担拼接与回退；零新增数据源/配置/状态文件；`deriveContinuationTargets` 与预算计数路径零改动。不引入 LLM 决策、不引入 daemon（不变量不变）。
