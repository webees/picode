### D077 摘要质量硬化（剔模板句 + 窗口可配置 · 本轮核心 1）

| # | 问题 / 候选 | 处置（决定） | 理由 |
|---|---|---|---|
| D077-1 | **模板句污染**：`historySummary` 的 outgoing 要点含上一轮 feed 全文（`READY_MESSAGE_TEXT`「你已就绪…」+ `CONTINUATION_PROMPT`「检测到本会话已空闲…」），下一轮摘要把这些模板句当「上一回合要点」注入（D076 (d) 1） | **`historySummary` 增可选 `stripNoise?: string[]`**：生成 outgoing 要点前，从文本中删除命中子串；剔除后为空 → 跳过该条要点（**条数统计仍保留事实计数**）。调用方各传各的模板（避免循环依赖）：`feedContinuation` 传 `[READY_MESSAGE_TEXT, CONTINUATION_PROMPT]`；`wakeWithOpencode` 传 `[READY_MESSAGE_TEXT]` | acceptance #1 直接保障面。**不内嵌在 transcript-store**（那是通用存储，不应知道 prompt 模板）→ 用 opts 传入，保持通用性；**不集中常量模块**（READY_MESSAGE_TEXT 在 opencode-adapter、CONTINUATION_PROMPT 在 continuation，合并会引入循环依赖）→ 各自调用方传自身已知模板。确定性、无 LLM、同输入同输出，符合 D003 |
| D077-2 | **剔除后空要点**：某 outgoing 条目全为模板句（如仅 ready 或仅续跑指令） | 剔除后为空 → 该条不出现在「要点」列表，但**头部统计计数不变**（条数/outgoing/incoming 是事实）；若最近窗口内全部条目被剔除 → `historySummary` 返回 null → feed 回退固定 `CONTINUATION_PROMPT`（与空转录同语义） | 统计保留事实、要点保留可读性；null 回退已有既有路径（D076），零新语义 |
| D077-3 | **摘要窗口硬编码**：feed 用 `maxEntries: 8`、re-spawn 用默认 20（E9 后续候选 #1） | **新增 `self_evolve.continuation.summary_entries: number`（默认 8）**，仅驱动 feed 路径（`feedContinuation` 传 `maxEntries: cont.summary_entries`）；**re-spawn 保持现 20 默认不动**（`wakeWithOpencode` 不读该字段） | E9 候选 #1 落地。默认 8 = 现 feed 行为逐字节不变（零回归）；re-spawn 的 20 是「全量恢复」语义、feed 的 8 是「上一回合增量」语义，**两个消费方意图不同，不强行统一**（避免改变 re-spawn 摘要内容） |
| D077-4 | **摘要标题常量重复**：`## 上一回合要点（转录摘要）` 字面量在 continuation.ts 与其测试各出现 | 提取 `CONTINUATION_SUMMARY_HEADER` 常量，`composeContinuationPrompt` 与测试共用 | 小重构防漂移（模板句列表将引用它）；纯文本，输出不变 |
| D077-5 | **re-spawn 摘要**：`wakeWithOpencode` 也消费 `historySummary`，同样受 ready 模板污染 | `wakeWithOpencode` 传 `stripNoise: [READY_MESSAGE_TEXT]`（其转录可能含续跑 feed 记录，但 CONTINUATION_PROMPT 剥离由 feed 路径负责，re-spawn 只剔 ready——够用且无循环依赖） | acceptance #4 不回归 re-spawn；机制与 feed 同源（E9 候选 #2「ready/re-spawn 一致化」的机制层达成，口径列表仍分开——留档后续可收拢） |
| D077-6 | **预算/幂等/纯函数回归** | `deriveContinuationTargets` 零改动；`feedContinuation` 只改摘要构造（`maxEntries`/`stripNoise` 传参），POST/计数/转录/重试路径不动；`historySummary` stripNoise 为纯函数新参数（默认空=现行为） | acceptance #4 验收面；既有 continuation 单测（含 null 回退、摘要注入、幂等）全绿即验收 |

### D078 续跑预算按角色差异化（平台席独立上限 · 本轮核心 2）

| # | 问题 / 候选 | 处置（决定） | 理由 |
|---|---|---|---|
| D078-1 | **单一预算**：`max_per_session` 对 task 绑定会话与平台席共用（`platform_seats=allow` 时平台席继承三角预算，E7 缓项候选 2） | **新增 `self_evolve.continuation.max_per_session_platform: number`（默认 2）**；`deriveContinuationTargets` 预算上限按 `taskId` 分流：task 绑定 → `max_per_session`；平台席（`taskIdOfAgent===null`）→ `max_per_session_platform`。`max_per_session` 语义不变 | 平台席为监测/调研型角色，续跑需求轻、防烧 token（R2-C2 哲学延续）；**更紧的独立默认 2** 是差异化意图本身——现 `allow` 配置（继承 5）会在升级后收紧到 2，属**有意的保守行为变更**，须在 DECISIONS/operations 显式注明 |

| D078-3 | **遥测口径**：`continuationTelemetry` per-session `max_per_session` 现为全局值 | session 级 `max_per_session` 反映**该会话适用上限**（task → `max_per_session`，平台席 → `max_per_session_platform`）；顶层 `ContinuationTelemetry` 增 `max_per_session_platform` 字段（新增字段，向后兼容） | D039 status 纯读快照三面口径一致（status/CLI/MCP 共用 `continuationTelemetry`），预算差异化后遥测须反映实际 cap，否则运营无法定位平台席预算耗尽 |
| D078-4 | **校验** | `validateConfig`：`max_per_session_platform` 须非负整数（与 `max_per_session` 同规则） | 对齐既有 continuation 校验模式；0=不限显式声明 |
| D078-5 | **配置文档/默认** | config.ts JSDoc + decision-catalog + operations 同步；默认 2 注明是「平台席保守独立预算」 | 差异化默认是有意的行为变更，必须文档留痕（D015 选项与默认仅 catalog） |
