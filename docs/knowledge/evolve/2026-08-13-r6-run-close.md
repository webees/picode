## Intent

前 run 收尾（goal completed）后平台席（无 task 绑定会话）残留 awake，占满
`sess_mgr.max_awake`，导致后续 run 无法唤醒新席位（Dashboard run 实测 product
acceptance 1/3 未满足）。本 run 三 product_acceptance：

1. run 收尾（goal completed/dissolved）时平台席自动休眠，不残留 awake
2. 提供会话残留检查/清理手段（CLI 可审计跨 run 残留）
3. `max_awake` 不再被已完成 run 的残留会话占满

## 决策要点（D072/D073）

- **D072 run 收尾自动休眠平台席**（C1）：
  - `sleepPlatformSeats`：遍历 SessionStore.list() 中 awake 且无 task 绑定（`taskIdOfAgent===null`）
    的平台席逐个 sleepAgent；幂等，重复调用零副作用
  - `closeRun`：applyEvent 补发 TASK_DISSOLVED（幂等，已 dissolved 无副作用）+ sleepPlatformSeats；
    双触发点 = guardianTick 终态 goal 分支（回报 `slept_platform`）+ `goal set-status` 终态分支
  - best-effort：单席/单任务失败不阻断整体；`setGoalStatus` 保持纯净；不引入规则表新事件
- **D073 session audit 跨 run 会话残留审计与清理**（C2）：
  - `deriveAuditReport` 纯派生（只读零写）：逐 run 读 goal.status + SessionStore → residual 标记 +
    跨 run 汇总 vs max_awake（`max_awake_exhausted`）；数据源 = runsRoot 下含 goal.yaml 的 run 目录
  - `cleanResidual`：对终态 run 残留调 C1 closeRun 原语；**动态 import 延迟接通**（C1 未合并仍可审计，
    --clean 报 NOT_FOUND）；best-effort 单 run 失败仅记 skipped
  - CLI `session audit --repo <path> [--clean] [--run <id>]`（noRun 跨 run）

## 剩余风险

- **残留回收依赖手动触发**：`--clean` 是运维显式命令，非自动清理；自动依赖 D072 的 guardian/CLI
  双触发点（best-effort），失败场景仍需 audit 兜底——新 run 前应跑 audit 闸门（operations.md 规程）
- **`--clean` 端到端未在 C2 实测**（D075 处置记录）：cleanResidual 依赖 C1 closeRun 动态 import 接通，
  真实终态 run 清理路径待 C3 合并后监督者实测；行为语义由单测守护

  量级增大时再评估是否需要索引缓存（当前 run 数规模无压力）
