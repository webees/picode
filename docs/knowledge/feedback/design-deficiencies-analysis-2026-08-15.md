## 🔴 已实证的重复性缺陷（每轮必踩，最该修）

### 1. worktree 环境初始化无自动化（每轮 3-5 次踩坑）
- 实测：node_modules 断链（悬空 symlink）→ 跨包解析落主仓旧 dist → 假红/TS 伪错 → 手工重建（W1/W2a/W2b/C2/C1 等，每轮至少 2 次）
- 缺陷：worktree 创建步骤是设计流程一部分，却没有固化——靠每个 sdet 各自发现修复
- 改进：`scripts/worktree-setup.sh`（add worktree + node_modules 自链 + @picode/* 本地链接），run-lead 建房一键执行

### 2. 测试环境假设靠人工纪律（HOME 隔离）
- 实测：真实 ~/.picode/config.yaml（opencode.enabled=true）导致不隔离直接 node --test 就 15-24 个假红
- 缺陷：环境假设没有强制入口——npm test 自带隔离，但针对性测试没有统一 wrapper
- 改进：`scripts/test-iso.sh`（统一 mktemp HOME + 参数透传）

### 3. 变更单问题模式高度重复（3/3 同型）
- 实测：co-001（夹具断言）/co-002（工具计数断言）/co-003（sleep 语义断言）——全部是"写集外既有测试断言过期"
- 缺陷：写集边界静态，功能变更天然过期相邻断言；无自动识别机制
- 改进：合并门前自动检测（diff 后全量，失败项若属"断言过期"类 → 自动记录 co-N 草案）

## 🟡 信息架构冗余

### 4. 三处文档重复：DECISIONS / catalog / E 系列纪要
- 实测：同一决策在 DECISIONS 详条、catalog、E 纪要各写一遍；E16-E18 与 catalog 大量重叠
- 缺陷：无单一事实源；写重复、读要跨三处核对
- 改进：E 纪要只写增量（决策引用编号 + 剩余风险/教训/候选）；catalog 只做索引

### 5. 验收基线数字不可比（环境漂移）
- 实测：基线 502→552→562→589→591→600→604→606 漂移（新增用例 + node 版本 + HOME 隔离差异混在一起）
- 缺陷：无统一基线记录格式
- 改进：evidence 头强制 `baseline: {env, commit, tests}` 三元组

## 🟠 架构盲区

### 6. 自演化只改代码，不评估流程
- 实测：三轮 run 全在修 bug/加功能/清理，无一轮审计流程本身；过度设计累积 3 轮才被 sponsor 提问暴露
- 缺陷：self_evolve 无"元评估流程"类型
- 改进：每 2-3 轮强制插流程元审计，或 E 纪要加"流程健康度"节

### 7. 子代理可靠性假设无兜底
- 实测：5+ 次会话 failed/零产出（庖丁、金乌×2、圭臬、秉烛不可达）→ 每次 run-lead 代提交/换帽
- 缺陷：无接管预案
- 改进：spawn 加"无提交超时"（2 轮无产出 → 自动通知 run-lead 接管）

### 8. Sponsor 反馈收集是被动的
- 实测：反馈沉淀都是 sponsor 主动要求才做
- 缺陷：设计缺"每轮结束自动征求 sponsor 反馈"环节
- 改进：每轮 complete 前 ask_user_question（"本轮哪里最繁琐？"）→ 直接进 knowledge/feedback/

## 🟢 验证过的良好设计（别动）

- 证据门禁 + 打回循环（4 次有效打回）
- worktree + 写集互斥（并行安全基础）
- 决策编号 + reserve/land（D001-D112 可追溯）
- 知识库结构（hr/feedback/evolve/handoffs 分区清晰）——缺的是消费回路

## §7. 文档生命周期授权试点（文档小组自主决定去留）

**目标**：验证文档小组能否自主决定资料去留（归档/合并/标注过时/淘汰）。
**授权内容**：每轮收尾，docs 小组对 knowledge/feedback 与相关文档执行"文档体检"：
1. 盘点：本周期沉淀的文档清单（新增/更新）
2. 判定：保留（仍有决策/复用价值）/ 合并（与既有文档重复）/ 归档（历史完成态）/ 标注过时（已被新决策取代）
3. 产出：去留清单（含理由），run-lead 审批后执行
**当前能力评估**：docs 小组有工具能力（读写 docs/ + 索引/归档），流程上缺授权章程——本试点补上。
